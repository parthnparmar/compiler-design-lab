❓ Help & Documentation

Quick guides to get you started with each module in Compiler Design Lab.

🔤 Lexical Modules
  • Enter a regex like a(b|c)* for NFA/DFA modules
  • Lexical Analyzer accepts full source code snippets
  • Results show transition tables and state diagrams
📐 Parser Modules
  • Enter grammar rules like E -> E + T | T
  • Use ε for empty (epsilon) productions
  • Non-terminals: uppercase; Terminals: lowercase/symbols
  • Enter test string space-separated: id + id * id
💻 Code Modules
  • Enter arithmetic expressions: x = b - c * 2
  • Three Address Code shows TAC, Quadruples, Triples
  • Code Generation produces assembly-like output
⚙ Advanced Modules
  • SDD/SDT: enter expressions for attribute evaluation
  • Compiler Phases: shows all 6 phases end-to-end
  • Expression Translation: Quadruples, Triples, Indirect Triples

💬 Frequently Asked Questions

What grammar format is accepted? ▼
Use -> to separate LHS from RHS, and | for multiple productions. Example: E -> T E' | T. Use ε for epsilon.
Why does it say "Grammar is not LL(1)"? ▼
The grammar may have left recursion or common prefixes. Remove left recursion and apply left factoring before using LL(1) parser. The tool does this automatically.
What is the difference between SLR, CLR, and LALR? ▼
SLR uses FOLLOW sets for reductions. CLR (Canonical LR) uses precise lookaheads per item — most powerful but largest tables. LALR merges CLR states with same LR(0) core — a good balance between power and size.
How do I enter tokens for parsing? ▼
Enter space-separated tokens. Example: id + id * id. The $ end-marker is added automatically.
Which module should I use first? ▼
Follow the numbered order: start with Regex to NFA (1), then NFA to DFA (2), then parsers (6–13), then code modules (8–10). The Compiler Phases module (11) gives a full end-to-end view.
