📚 Phase 1: Lexical Analysis Theory

Lexical Analysis is the first phase of compilation. It reads the source code character by character and converts it into meaningful tokens (lexemes). The lexical analyzer (scanner) identifies keywords, identifiers, operators, constants, and removes whitespace and comments.


Key Functions:

  • Token Recognition: Identifies different types of tokens
  • Pattern Matching: Uses regular expressions
  • Symbol Table: Stores identifier information
  • Error Detection: Reports lexical errors

📚 Phase 2: Syntax Analysis Theory

Syntax Analysis (Parsing) is the second phase that takes tokens from lexical analysis and builds a parse tree. It checks if the token sequence follows the grammatical rules of the programming language. The parser uses Context-Free Grammar (CFG) to validate syntax.


Key Functions:

  • Parse Tree Construction: Builds hierarchical structure
  • Syntax Validation: Checks grammar rules
  • Error Recovery: Handles syntax errors
  • Derivation: Shows how tokens derive from grammar

📚 Phase 3: Semantic Analysis Theory

Semantic Analysis checks the semantic correctness of the program. It ensures that the program makes sense according to language rules. This phase builds and maintains the symbol table, performs type checking, and validates scope rules.


Key Functions:

  • Type Checking: Ensures type compatibility
  • Symbol Table: Stores variable information
  • Scope Resolution: Manages variable scope
  • Declaration Checking: Validates declarations

📚 Phase 4: Intermediate Code Generation Theory

Intermediate Code Generation produces an intermediate representation (IR) of the source code. Three Address Code (TAC) is commonly used where each instruction has at most three operands. This phase bridges high-level source code and low-level machine code.


Key Functions:

  • TAC Generation: Creates three-address instructions
  • Temporary Variables: Uses t1, t2, etc.
  • Expression Simplification: Breaks complex expressions
  • Platform Independence: Machine-independent code

💡 Example 1: x = b - c * 2

t1 = c * 2
t2 = b - t1
x = t2

💡 Example 2: I = p * n * r / 100

t1 = p * n
t2 = t1 * r
t3 = t2 / 100
I = t3

📚 Phase 5: Code Optimization Theory

Code Optimization improves the intermediate code to make it faster and more efficient. It eliminates redundant operations, performs constant folding, removes dead code, and optimizes loops without changing the program's output.


Key Techniques:

  • Constant Folding: Evaluates constant expressions at compile time
  • Dead Code Elimination: Removes unreachable code
  • Common Subexpression Elimination: Reuses computed values
  • Loop Optimization: Improves loop performance

📚 Phase 6: Target Code Generation Theory

Target Code Generation is the final phase that produces machine code or assembly code for the target architecture. It allocates registers, manages memory, and generates executable instructions. The code must be efficient and correct.


Key Functions:

  • Register Allocation: Assigns variables to registers
  • Instruction Selection: Chooses appropriate machine instructions
  • Memory Management: Handles stack and heap
  • Code Emission: Generates final executable code

📚 Regex to NFA Theory

Regular Expression to Non-deterministic Finite Automaton (NFA) conversion uses Thompson's Construction algorithm. It builds an NFA for each basic regular expression and combines them using union, concatenation, and Kleene star operations.


Key Concepts:

  • Thompson's Construction: Systematic NFA building
  • Epsilon Transitions: Empty string transitions
  • Union Operation: a|b creates parallel paths
  • Concatenation: ab creates sequential states
  • Kleene Star: a* creates loops with epsilon

💡 Example: (a|b)*c

q4 --ε--> q5

📚 NFA to DFA Theory

NFA to DFA conversion uses Subset Construction (Powerset Construction) algorithm. Each DFA state represents a set of NFA states. The algorithm computes epsilon closures and transitions for all input symbols.


Key Steps:

  • Epsilon Closure: Find all states reachable via ε-transitions
  • Subset Construction: Create DFA states from NFA state sets
  • Transition Table: Compute moves for each symbol
  • Final States: Any set containing NFA final state

💡 Example: NFA with ε-transitions

📚 DFA Minimization Theory

DFA Minimization reduces the number of states in a DFA while preserving its language. It uses the Table-Filling Algorithm (Myhill-Nerode theorem) to identify and merge equivalent states.


Key Steps:

  • Remove Unreachable States: Eliminate states not reachable from start
  • Partition States: Separate final and non-final states
  • Refinement: Split partitions based on transitions
  • Merge Equivalent States: Combine indistinguishable states

📚 Direct DFA Construction Theory

Direct DFA construction builds a DFA directly from a regular expression without creating an intermediate NFA. It uses position numbering and computes followpos, firstpos, and lastpos functions.


Key Functions:

  • nullable: Can the expression match empty string?
  • firstpos: Set of positions that can match first symbol
  • lastpos: Set of positions that can match last symbol
  • followpos: Set of positions that can follow a position

💡 Example: (a|b)*abb#

📚 LL(1) Parser Theory

LL(1) is a top-down parsing technique that reads input Left-to-right, produces Leftmost derivation, and uses 1 lookahead symbol. It uses FIRST and FOLLOW sets to build a predictive parsing table.


Key Concepts:

  • FIRST Set: First terminals that can appear in derivation
  • FOLLOW Set: Terminals that can follow a non-terminal
  • Parsing Table: M[A, a] = production to use
  • No Left Recursion: Grammar must be left-factored

💡 Example Grammar:

E → T E'
E' → + T E' | ε
T → F T'
T' → * F T' | ε
F → ( E ) | id

📚 SLR Parser Theory

SLR (Simple LR) is a bottom-up parsing technique that uses LR(0) items and FOLLOW sets. It builds a canonical collection of LR(0) items and constructs ACTION and GOTO tables for shift-reduce parsing.


Key Concepts:

  • LR(0) Items: Productions with dot indicating position
  • Closure: Add items for non-terminals after dot
  • GOTO Function: Transition between item sets
  • ACTION Table: Shift, Reduce, Accept, or Error
  • GOTO Table: State transitions for non-terminals

💡 Example Grammar:

E → E + T | T
T → T * F | F
F → ( E ) | id

Augmented Grammar:

E' → E
E → E + T | T
T → T * F | F
F → ( E ) | id

Sample LR(0) Items (State I0):

E' → •E
E → •E + T
E → •T
T → •T * F
T → •F
F → •( E )
F → •id

Parsing Actions:

  • Shift: Push input symbol and next state
  • Reduce: Pop symbols, push non-terminal
  • Accept: Parsing successful
  • Error: Syntax error detected
